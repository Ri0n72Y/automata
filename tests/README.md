# 测试组织规范

本目录按被测契约和边界维度组织，不按缺陷发现顺序组织。

## 测试层级

### Contract

验证单个模块的长期契约、输入等价类和边界。

常见内容：

- 有效输入的正常域；
- 上下界及界外值；
- 状态转换；
- 原子性与幂等性；
- 共享不变量。

文件命名：

```text
<module>_contract_test.gd
<module>_state_machine_test.gd
<module>_lifecycle_test.gd
```

### Integration

验证多个模块之间的接线和一个完整用户流程。集成测试不重复枚举底层模块已经覆盖的全部边界。

文件命名：

```text
<scene>_<flow>_integration_test.gd
```

## 新增回归案例

发现缺陷后，依次判断：

1. 缺陷违反了哪个既有契约；
2. 当前案例表缺少哪个等价类或边界；
3. 是否需要补充新的共享不变量；
4. 是否只是场景接线问题。

优先在现有案例表中增加一行。只有出现新的独立职责时才新建测试文件。

## 测试实现约定

- 案例差异使用具名表驱动数据表示；
- 多个案例共享统一的不变量检查；
- 拒绝路径必须验证状态不被部分修改；
- 生命周期测试必须验证创建、替换、取消和退出清理；
- 场景测试只保留关键用户闭环；
- `tests/support/contract_test.gd` 只提供断言统计和退出，不隐藏业务步骤；
- 每个 `.gd` 测试脚本提交对应 `.gd.uid`；
- 测试未实际运行时必须记录为“未执行”，不得写成“通过”。

## 当前目录分工

```text
tests/grid/       网格模型、地砖视图和调试视图
tests/camera/     相机构图、旋转状态机和点击映射
tests/input/      地面/车辆选择、预测和快捷键输入
tests/vehicles/   车辆定义、运行时、命令、执行和视觉契约
tests/scene_01/   Scene 01 初始化、资源结构和用户流程集成
tests/support/    通用测试支持代码
```
